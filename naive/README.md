# Notes API

REST API для заметок с тегами на Node.js + Express. Данные хранятся
в обычном JSON-файле `data/notes.json` — никакой базы не нужно.

## Запуск

```bash
npm install
npm start
```

Сервер поднимется на `http://localhost:3000`. Порт меняется переменной
окружения `PORT`:

```bash
PORT=8080 npm start
```

Файл `data/notes.json` создаётся сам при первом запросе.

## Модель заметки

```json
{
  "id": "e7205a2f-b49b-4fbe-b22c-bcf1b8123caf",
  "title": "Купить молоко",
  "body": "2 литра",
  "tags": ["дом", "покупки"],
  "createdAt": "2026-08-14T07:53:14.959Z",
  "updatedAt": "2026-08-14T07:53:14.959Z"
}
```

Обязательное поле только `title`. Теги приводятся к нижнему регистру,
обрезаются по краям и дедуплицируются: `["Дом", "дом", " ДОМ "]` превратится
в `["дом"]`.

## Эндпоинты

| Метод    | Путь         | Что делает                          |
| -------- | ------------ | ----------------------------------- |
| `GET`    | `/health`    | Проверка, что сервер живой          |
| `GET`    | `/notes`     | Список заметок с фильтрами          |
| `POST`   | `/notes`     | Создать заметку → `201`             |
| `GET`    | `/notes/:id` | Одна заметка                        |
| `PUT`    | `/notes/:id` | Заменить заметку целиком            |
| `PATCH`  | `/notes/:id` | Обновить только присланные поля     |
| `DELETE` | `/notes/:id` | Удалить заметку → `204`             |
| `GET`    | `/tags`      | Все теги со счётчиком использований |

### Параметры `GET /notes`

| Параметр | Пример          | Описание                                       |
| -------- | --------------- | ---------------------------------------------- |
| `tag`    | `?tag=работа`   | Фильтр по тегу, можно повторять несколько раз  |
| `tags`   | `?tags=дом,еда` | То же самое, но списком через запятую          |
| `match`  | `?match=all`    | `any` (по умолчанию) или `all` — все теги сразу |
| `q`      | `?q=молоко`     | Поиск подстроки в `title` и `body`             |
| `limit`  | `?limit=10`     | Сколько вернуть                                |
| `offset` | `?offset=20`    | Сколько пропустить                             |

Ответ: `{ "total": 42, "items": [...] }`. `total` — количество после фильтров,
до применения `limit`/`offset`. Сортировка — новые сверху.

## Примеры

```bash
# создать
curl -X POST http://localhost:3000/notes \
  -H "Content-Type: application/json" \
  -d '{"title":"Купить молоко","body":"2 литра","tags":["дом","покупки"]}'

# заметки с тегом "работа"
curl "http://localhost:3000/notes?tag=работа"

# заметки, у которых есть оба тега сразу
curl "http://localhost:3000/notes?tags=работа,срочно&match=all"

# поиск по тексту
curl "http://localhost:3000/notes?q=молоко"

# все теги с частотой
curl http://localhost:3000/tags

# поменять только теги, остальное не трогать
curl -X PATCH http://localhost:3000/notes/<id> \
  -H "Content-Type: application/json" \
  -d '{"tags":["дом","срочно"]}'

# удалить
curl -X DELETE http://localhost:3000/notes/<id>
```

## Ошибки

Единый формат: `{ "error": "текст" }`.

- `400` — нет `title`, `tags` не массив строк, битый JSON, кривые `limit`/`offset`
- `404` — заметки с таким `id` нет, либо неизвестный маршрут
- `500` — всё остальное

## Как устроено

- `server.js` — маршруты, разбор query-параметров, обработчик ошибок
- `notes.js` — вся логика: валидация, фильтрация, CRUD, подсчёт тегов
- `storage.js` — чтение и запись JSON-файла
- `data/notes.json` — сами данные

Запись идёт во временный файл с последующим `rename`, поэтому файл не останется
наполовину записанным, если процесс упадёт. Параллельные записи выстроены
в очередь, чтобы два одновременных запроса не затёрли друг друга.

## Ограничения

Файловое хранилище рассчитано на один процесс: весь файл читается и пишется
целиком на каждый запрос. Для пары тысяч заметок это незаметно, дальше нужна
нормальная БД. Аутентификации нет.
